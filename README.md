# Pixel Portfolio

Одностраничный сайт-портфолио в виде окна пиксельной игры.
Чистые HTML + CSS + vanilla JS. Без сборщиков, без npm, без зависимостей.

**Открывается двойным кликом по `index.html`.** Заливается как есть на GitHub
Pages / Netlify — все пути относительные, шрифты лежат локально.

---

## Принятые решения

Эти вопросы решены без переспрашивания. Всё меняется в один шаг — где именно,
указано в правой колонке.

| Вопрос | Решение | Где поменять |
|---|---|---|
| Язык сайта | **Английский** везде: UI, alt, title, meta, заглушки | `data.js` + `<noscript>` в `index.html` |
| Второй уровень на десктопе | **Замена контента в той же правой панели** (не аккордеон под карточкой): деталь получает всю ширину и высоту, и логика совпадает с мобильной модалкой | `js/app.js`, функция `apply()` |
| Второй уровень на мобилке | **Полноэкранная модалка** в стиле того же окна | `js/app.js`, `openModal()` |
| Потеря сетки из виду | Компенсируется **лентой мини-превью соседей** над деталью | `js/render.js`, функция `detail()` |
| Контент | **Плейсхолдеры** — 3 проекта, 2 места работы, 3 хобби | `data.js` |
| Небо и облака | **Чистый CSS** (инлайновые SVG-тайлы), без картинок | `css/06-sky.css` |
| Иконки статов и превью карточек | **Пиксельные SVG-заглушки** в коде | `js/render.js`, объект `ICONS` |
| Шрифты | **Локально** в `assets/fonts` (~22 КБ), сайт работает офлайн | `css/01-tokens.css` |
| Пути | **Относительные** (`./assets/...`) — работает и с `file://`, и в подпапке на GitHub Pages | — |
| Звук | **Выключен по умолчанию**, состояние в `localStorage` | `js/audio.js` |
| Семантика навигации | **`nav` + `aria-current`**, а не паттерн табов (обоснование ниже) | `index.html` |
| Java/Maven-скелет | **Удалён.** Корень репозитория = корень сайта | — |

## Как отредактировать сайт

Всё содержимое — в **`data.js`**. Разметку и стили трогать не нужно.
Ошибки в данных проверяются на старте и печатаются в консоль браузера
(F12 → Console) понятным текстом.

### Частые правки

| Что нужно | Где |
|---|---|
| Поменять имя в шапке | `meta.name` |
| Добавить проект | новый объект в `sections` → `projects` → `items` |
| Убрать второй уровень у раздела | `mode: "page"` + заполнить `page` |
| Поменять реплику персонажа | `sections[].bubble` |
| Отключить слежение за курсором | убрать блок `character.gaze` |
| Добавить действие | новый объект в `actions.items` |
| Поменять реплику действия | `actions.items[].line` |
| Поменять строку под сеткой | `actions.items[].feedback` |
| Поменять LVL или шкалу | `profile.level`, `levelFilled`, `levelTotal` |
| Поменять STATUS / LOCATION / NOW | `profile.rows` |
| Поменять ссылки в подвале | `footer.links` |
| Расширить мёртвую зону | `character.gaze.deadZone` |
| Поменять цвета | `css/01-tokens.css`, блок `:root` |
| Поменять скорость печати | `--type-speed` в токенах и `speed` в `js/app.js` |

**Реплики персонажа** живут в двух местах: `actions.items[].line` — то, что
он говорит на действие, `sections[].bubble` — на выбранный раздел,
`character.idleBubble` — когда ничего не выбрано. Приоритет сверху вниз:
временная реплика (наведение, фокус, нажатие) → включённый переключатель →
раздел → дефолт. **Одна реплика за раз**, галерей состояний нет.

**Иконки действий и подвала** — это имена из объекта `ICONS` в
`js/render.js`. Там же они и рисуются: массив прямоугольников
`[цвет, x, y, ширина, высота]` по сетке 16×16. Готовые имена:
`note`, `shirt`, `clock`, `briefcase`, `monitor`, `code`, `envelope`,
`badge`, `document`, `star`, `heart`, `item`. Неизвестное имя
молча подменяется заглушкой, сайт не ломается.

Логотипы GitHub и LinkedIn намеренно не воспроизводятся: в подвале стоят
нейтральные глифы, а название несут `title` и `aria-label`.

⚠️ **`<noscript>` в `index.html`** содержит продублированные вручную имя,
описание и контакты. Без JS страница была бы пуста — весь контент живёт
в `data.js`. Если меняете контакты, поправьте и там.

## Второй комплект спрайтов (CHANGE OUTFIT)

Кнопка **CHANGE OUTFIT** сейчас в панели есть, выглядит как primary-действие,
но выключена: `disabled`, с подсказкой «coming soon». Смена наряда требует
второго комплекта из девяти направлений, которого пока нет.

Чтобы включить, нужны три шага:

1. Положить девять файлов в **`assets/sprites/lecture/`** с ровно теми же
   именами, что и в основном комплекте:

   ```
   look-up-left.png    look-up.png     look-up-right.png
   look-left.png       look-center.png look-right.png
   look-down-left.png  look-down.png   look-down-right.png
   ```

   Размер — **128×128 PNG с прозрачностью**, тот же, что у основного набора.
   Персонаж должен стоять в кадре ровно так же, иначе при переодевании он
   дёрнется: bbox основного комплекта — 52×120 пикселей, отсчёт от верха
   кадра y=4.

2. В `data.js` снять флаг у комплекта:
   `character.outfits.lecture.enabled: true`

3. Там же снять флаг у действия: убрать `enabled: false` у элемента
   `actions.items` с `id: "outfit"`.

Реплика `THIS IS HOW YOU SEE ME ON LECTURES` уже заведена в
`character.states.outfit.line` — трогать её не нужно.

Пока хотя бы один из флагов выключен, `js/store.js` пишет предупреждение в
консоль и выводит кнопку недоступной. Сама подмена спрайтов не реализована:
включать её будем, когда файлы появятся.

## Спрайты нужно переэкспортировать

Персонаж выводится размыто, и **CSS это не лечит**. Замеры:

| | значение |
|---|---|
| `naturalWidth` / `naturalHeight` | 128 × 128 |
| размер на экране | 384 × 384 |
| отношение | ровно **3.0** — целое, дробного масштабирования нет |
| `image-rendering` | `pixelated` |
| `devicePixelRatio` | 1 |

Масштаб целый, фильтр правильный — значит дело в самом файле. Разбор
содержимого `look-center.png` это подтверждает:

- **2592 уникальных цвета** в кадре 128×128 (у пиксель-арта их десятки);
- **ни одного полностью непрозрачного пикселя** — вся картинка сглажена;
- половина переходов вдоль строки через тело — мягкие градиенты.

Исходники 1254×1254 тоже без пиксельной сетки: длины одноцветных участков
равны 1, уникальных цветов больше 14 000. То есть это не увеличенный
пиксель-арт, а гладкий рендер, и уменьшение до 128 сохранило сглаживание.

**Что нужно от вас:** сохранить кадры из Aseprite **в исходном масштабе
1:1**, без `Scale` при экспорте. Если холст 64×64 — файл должен быть
64×64, а не 1254×1254. Увеличением займётся CSS: он умножает на целое
число и не сглаживает.

Размер холста подойдёт любой в диапазоне примерно 48–128px по стороне;
после этого достаточно поменять `--char-size` в `css/01-tokens.css` под
новую сторону, лестница масштабов подстроится.

Со стороны кода одно исправление всё же было: анимация дыхания
интерполировала `translateY` непрерывно и ставила спрайт на дробный
пиксель (`-0.9px`), что размывало даже резкую картинку. Теперь кадры
дискретные и сдвиг всегда целый.

## Кадры действий

Папки `assets/sprites/<action>/` — `playMusic`, `think`, `drinkEnergydrink`,
`debug`, `takePhoto`, `sayHi` — сейчас лежат с исходными кадрами под
UUID-именами. **Из имён не восстановить порядок кадров**, а для анимации он
критичен, поэтому автоматически они не подключены: действия работают без
неё — реплика, звук и накладки играют, спрайт остаётся тем, что подставил
`gaze.js`.

Чтобы включить анимацию действия, нужно два шага:

1. Положить кадры **отдельными файлами** в ту же папку, в порядке
   проигрывания: `01.png`, `02.png`, … `10.png`. Спрайт-лист одним файлом не
   поддерживается — покадрово проще подменять `src` и не считать смещения.
   Формат тот же, что у `cursorWatcher`: **128×128 PNG с прозрачностью**,
   персонаж в кадре стоит так же, иначе он дёрнется при переключении.

2. Перечислить их в `data.js` → `actions.frames`:

   ```js
   frames: {
     think: ["01.png", "02.png", "03.png", "04.png"],
     …
   }
   ```

Пока список пуст, действие просто не анимируется, ничего не ломается и
битых картинок не появляется.

**Повторный клик во время проигрывания перезапускает анимацию с начала**, а
не игнорируется — так кнопка всегда откликается на нажатие. Переключается
флагом `actions.restartOnRepeat`.

Если предпочитаете, чтобы порядок определил я: переименуйте ничего не надо,
просто скажите — разложу кадры по времени изменения файла и покажу
раскадровку на проверку до того, как что-то подключать.

## Спрайты персонажа

Слежение за курсором работает на папке **`assets/sprites/cursorWatcher/`** —
путь берётся из `data.js` → `character.gaze.base`. Там девять кадров
**128×128 PNG с прозрачностью**:

```
look-up-left    look-up     look-up-right
look-left       look-center look-right
look-down-left  look-down   look-down-right
```

`look-center` — взгляд прямо, значение по умолчанию и то, что показывается
на тач-устройствах и при `prefers-reduced-motion`.

### Что было сделано с исходниками

Исходные файлы были **1254×1254 RGB без альфа-канала**, с клетчатым фоном,
впечатанным прямо в пиксели, и весили ~1 МБ каждый. На розовом дисплее
вместо прозрачности была бы серая шахматка. Поэтому они пересобраны:

1. Фон вырезан **флуд-филлом от краёв** — не по цвету глобально, иначе
   пострадали бы светлые пиксели внутри силуэта (линзы очков, кожа).
2. Посчитан **общий bounding box по всем девяти кадрам** и применён ко всем
   одинаково. Если кадрировать каждый по своему содержимому, персонаж будет
   дёргаться при каждой смене направления.
3. Даунскейл до 128×128 **box-фильтром в premultiplied alpha** — иначе по
   краю силуэта полупрозрачные пиксели притянули бы к себе цвет фона.

Итог: **11 КБ на файл вместо 1 МБ**, 108 КБ на все девять.

Оригиналы сохранены в `references/sprites-source/` (папка в `.gitignore`,
в репозиторий и деплой не попадает). Скрипт пересборки одноразовый и в
проекте не остался — если будете менять арт, проще экспортировать сразу
128×128 PNG с настоящей прозрачностью.

⚠️ Исходники были ресемплены при генерации, поэтому чёткой пиксельной сетки
в них нет. `image-rendering: pixelated` включён, но предел резкости задан
исходником, а не кодом.

## Остальные ассеты (опционально)

Сайт работает без них — везде пиксельные заглушки в коде.

| Файл | Исходник | На экране | Приоритет |
|---|---|---|---|
| `assets/icons/stat-<id>.png` | **16×16** | 32×32 (×2) | 🟡 ×5 |
| `assets/icons/app.png` | **16×16** | 32×32 | 🟡 |
| `assets/cards/<id>.png` | **64×64** | 128×128 (×2) | 🟡 |
| `assets/cards/<id>@hero.png` | **192×128** | 384×256 (×2) | 🟡 |
| `assets/sky/cloud-*.png` | тайл, бесшовный по X | ×2 | 🟢 |

**Правила для всех PNG:** экспорт 1:1 без сглаживания (nearest neighbour),
прозрачный фон, палитра из `css/01-tokens.css`. **Не масштабируйте в
редакторе** — увеличивает CSS, целыми множителями.

Курсоры (`assets/cursors/arrow.png`, `hand.png`) уже готовы — 32×32.
Chrome молча игнорирует cursor-картинки крупнее 32×32, так что этот размер
менять нельзя.

### Важные решения

**Классические `<script>`, а не модули.** Через `file://` браузер блокирует
`import` по CORS, а сайт должен открываться двойным кликом. Порядок тегов
в `index.html` = порядок зависимостей.

**URL — единственный источник истины.** Клик только меняет хэш; всё рисует
подписчик на `hashchange`. Отсюда бесплатно работают кнопка «Назад»,
deeplink и отсутствие рассинхрона состояния.

**Ступенчатые углы без `border-radius`.** `.px-box` собирает контур из четырёх
`box-shadow` — каждый копия бокса, сдвинутая в свою сторону. Углы остаются
пустыми. Следствие: контур рисуется **снаружи**, поэтому `overflow: hidden`
на `.px-box` вешать нельзя (срежет рамку), а у родителей нужен `padding`
или `gap` не меньше `--bd`.

**Навигация — `nav` + `aria-current`, а не табы.** Паттерн табов по APG требует
roving tabindex: один Tab-стоп на весь список и переключение стрелками.
Здесь нужен обычный Tab по каждому стату, плюс структура двухуровневая —
это навигация, а не табы. Стрелки ↑↓, Home/End работают сверху, как бонус.

**Печать и скринридеры.** Печатающийся слой целиком `aria-hidden`, полный текст
лежит рядом в `.sr-only` и читается сразу и один раз. `aria-live` здесь был бы
вредом — скринридер начал бы тараторить по букве. Высоту держит «призрак»
(`.typed__ghost`, `visibility: hidden`), иначе панель дёргалась бы на
каждом символе.

**Двойная рамка (`.px-double`).** Тёмная 4px, белая прослойка 4px, тёмная
4px — замерено пипеткой по макету. Собирается тремя кольцами `box-shadow`
внутри `.px-box`: первая тень рисуется поверх, поэтому каждое следующее
кольцо видно только там, где его не закрыло предыдущее, и углы остаются
ступенчатыми на всех трёх уровнях. Следствие: контур выходит на **12px**
за бокс, а не на 4, поэтому у панелей с двойной рамкой `margin: 16px` —
12 на рамку и 4 про запас, потому что `fr`-колонки дают дробную ширину и
срезали внешнее кольцо на пиксель.

**Состояния персонажа.** Сцена — один `<img>` внутри обёртки `#stage`.
Анимации состояний (`idle` — дыхание, `dance` — покачивание) висят на
обёртке, а не на картинке: `src` у `<img>` принадлежит `gaze.js`, он
подставляет туда направление взгляда. Поэтому персонаж одновременно следит
за курсором и дышит, и ничего не конфликтует. Состояние — это
`data-state` на обёртке, одно за раз. При `prefers-reduced-motion`
выставляется ещё и `data-motion="off"`, и анимация не навешивается вовсе.

**Музыка.** Генерируется теми же square-осцилляторами, что и блипы, без
mp3. Ноты планируются барами вперёд по `ctx.currentTime` — `setInterval`
сам по себе плывёт и дросселируется в фоновой вкладке. **Автостарта нет и
быть не может:** браузер блокирует звук до жеста пользователя, и кнопка
PLAY MUSIC и есть этот жест. Состояние пишется в `localStorage`, но при
следующем заходе НЕ восстанавливается — Safari молча откажет, и кнопка
будет врать, что музыка играет. Нажатие PLAY MUSIC заодно снимает общий
mute, иначе кнопка молчала бы.

**Мобильная раскладка.** Порядок блоков: шапка → реплика → персонаж →
профиль → **действия** → навигация → контент → подвал. Действия стоят сразу
под персонажем намеренно: нажал — реакцию видно на том же экране, без
прокрутки. Проверено замером на 390×844: персонаж, окно диалога и первая
кнопка действия помещаются без скролла, и это закреплено тестами.

Левая колонка раскрывается через `display: contents`, чтобы её дети встали
в сетку рабочей области по отдельности. Важная тонкость: `display: contents`
меняет дерево боксов, но не DOM, поэтому селектор `.workspace > *` до них уже
не достаёт — `min-height` приходится снимать явно.

Ленты действий и навигации скроллятся горизонтально со `scroll-snap`. Им
обязателен `flex: 0 0 auto`: `overflow-x: auto` делает элемент скролл-
контейнером по **обеим** осям, а у такого минимальный размер во flex равен
нулю — без этого ряд схлопывается, а кнопки вылезают за панель.

**Слежение за курсором (`js/gaze.js`).** Круг вокруг центра спрайта делится
на 8 секторов по 45°. Три вещи, без которых оно работает плохо:

- *Гистерезис.* На стыке секторов курсор дрожит на доли градуса, и картинка
  начинает мигать. Направление меняется, только когда курсор ушёл от центра
  ТЕКУЩЕГО сектора дальше, чем на 22.5° + запас. То же на границе мёртвой
  зоны: входим на 60px, выходим на 68px.
- *Один пересчёт на кадр.* `mousemove` сыплется чаще, чем браузер рисует, а
  `getBoundingClientRect` в обработчике — это принудительный reflow на каждое
  событие. Обработчик только запоминает координаты, работа идёт в `rAF`.
- *Предзагрузка.* Без неё первый поворот головы мигнёт пустотой.

Геометрия пересчитывается на `resize` и на `scroll` (с `capture: true` —
чтобы ловить и скролл внутренних панелей, а не только страницы).
`MIRA.gaze.update()` форсирует пересчёт, если лейаут поменяли программно.

**Только целые множители спрайтов.** Спрайт 128×128, `--char-scale`
переключается ступенчато: **2** (→256px) и **1** (→128px) ниже 560px.
Дробное масштабирование ломает `image-rendering: pixelated`: часть
«пикселей» станет 3px, часть 4px.

## Клавиатура

| Клавиша | Действие |
|---|---|
| `Tab` / `Shift+Tab` | по статам и элементам |
| `Enter` / `Space` | активировать |
| `↑` `↓` | между статами |
| `Home` / `End` | первый / последний стат |
| `Esc` | закрыть деталь или модалку |
| `M` | включить/выключить звук |

Звук по умолчанию **выключен**, состояние живёт в `localStorage`.

## Грабли, на которые уже наступили

Если будете править код — эти места чинились по факту, не по наитию.

- **В `Press Start 2P` нет `←` (U+2190) и `↗` (U+2197).** Браузер подставлял
  глиф из фоллбэк-шрифта, и он выбивался из стиля. Стрелки на кнопке BACK,
  в подсказке и у внешних ссылок рисуются пикселями (`ICONS.arrowLeft`,
  `ICONS.external` в `js/render.js`). Не возвращайте их в `data.js` текстом.
- **`min-height: 0` нужен на десктопе и вреден в вертикальной раскладке.**
  Без него grid-колонки не сжимаются и внутренний скролл не включается.
  Но при вертикальной укладке свободного места отрицательно много, и grid
  начинал ужимать строку персонажа ниже её содержимого — спрайт наезжал на
  спич-бабл. В блоке `<= 900px` он снят, строки там по контенту.
- **`focus()` прокручивает элемент в видимую область** и затирал позицию
  скролла, восстановленную после BACK. Везде используется
  `focus({ preventScroll: true })`.
- **`1fr auto 1fr` в title bar** заставляет обе боковые колонки быть не уже
  самой широкой из них. Четыре кнопки справа делали окно шире вьюпорта на
  телефоне. Ниже 560px декоративные кнопки скрыты, сетка `auto 1fr auto`.
- **Гамбургер сворачивает список статов**, а не открывает отдельное меню: в
  вертикальной раскладке статы и так на экране, и полезнее их убрать, чтобы
  контент был ближе. При выборе стата список сворачивается сам.
- **SVG без `width`/`height` схлопывается в 300x150** и ломает иконки.
  Правило в `02-base.css` заставляет их занимать контейнер целиком.
- **Порог «страница не скроллится» пришлось поднять с 640px до 760px**
  по высоте. Панель INVENTORY и статы персонажа требуют больше места, и на
  коротком вьюпорте нижний ряд инвентаря просто обрезало. Строки сетки
  инвентаря при этом тянутся (`grid-auto-rows: minmax(36px, 1fr)`), а не
  держат жёсткий `aspect-ratio` — иначе они не ужимались бы вовсе. На тач-
  ширинах (≤900px) квадратность и минимум 44px возвращаются.
- **Исходные спрайты пришли без альфа-канала**, с шахматкой, впечатанной в
  пиксели. `file` показывал `8-bit/color RGB` — три канала, не четыре.
  Проверяйте это перед тем, как класть картинку на цветной фон.
- **Слежение за курсором и позы по секциям конфликтуют.** Когда `gaze`
  включён, картинкой владеет `gaze.js` и `sections[].pose` игнорируется:
  иначе рендер пересоздавал бы `<img>`, сбрасывая состояние слежения и мигая.
- **Скролл сетки запоминается у того элемента, который реально скроллит:**
  `.content` на десктопе, `.workspace` на мобилке (функция `scroller()`
  в `app.js`). Иначе память молча не работала на телефоне.

## Автотесты

`selftest.html` — та же страница плюс скрипт с проверками. Откройте её в
браузере: результаты появятся в левом верхнем углу. Покрыто **117 проверок**.

Слежение за курсором: выбор сектора по углу для всех восьми направлений,
границы секторов, мёртвая зона в обе стороны, гистерезис, загрузка всех
девяти спрайтов, отсутствие обработчиков при `prefers-reduced-motion` и на
тач-устройствах, возврат в `look-center`.

Инвентарь и статы: счётчик COLLECTED сверяется с данными и пересчитывается
при их изменении, `aria-label` и `title` у каждой плитки, пунктир и «?» у
закрытой, число ячеек шкалы и закрашенных — из `profile`.

Стрелки: шаг вперёд и назад, заворот через оба края, полный круг
возвращает на старт, шаг из пустого состояния, обновление хэша и подсветки.

Плюс вся навигация, фокус, печать, звук, подвал и геометрия.

Набор знает про ширину экрана: часть проверок относится только к мобильной
раскладке и на широком вьюпорте помечается как пропущенная, а деталь ищется
в модалке вместо правой панели.

### Границы центральной колонки

Отдельный блок проверяет, что центральная панель и всё её содержимое
помещаются внутрь рабочей области: верх не выше низа заголовка окна, низ
не ниже внутренней границы окна, дети не выходят за панель. Прогоняется на
1600×1100, 1280×800 и 390×844.

### Рамки

Отдельный блок проверок обходит все коробки с рамкой и следит, что рамка
есть со всех четырёх сторон, одинаковой толщины, на целых пикселях и не
срезана `overflow: hidden` у родителя. Шапка окна намеренно отделена только
нижней линией — это разделитель внутри окна, а не отдельная коробка.

На момент последнего прогона:
- **166** зелёных на 1600×1100;
- **179** зелёных на 390×844 (те же плюс мобильные).

### Прогон во всех четырёх браузерах

`tools/xbrowser.py` гоняет тот же набор в **WebKit, Firefox и Chromium** на
обоих вьюпортах. WebKit — это движок Safari, то есть покрытие реальное, а не
«на глаз». Edge использует Chromium, отдельного движка у него нет.

Node для этого не нужен:

```bash
python3 -m venv .venv
.venv/bin/pip install playwright
.venv/bin/playwright install webkit firefox chromium   # ~1 ГБ в кеш
.venv/bin/python tools/xbrowser.py
```

Скрипт возвращает код 1, если хоть одна проверка где-то упала, — можно
вешать в CI.

Последний прогон: **все шесть комбинаций зелёные** (3 движка × 2 вьюпорта).
Дополнительно сверены попиксельно: спрайт персонажа рендерится **идентично**
во всех трёх движках (0.000% различий), вычисленные стили рискованных свойств
(`image-rendering`, `aspect-ratio`, `clip-path`, `display: contents`, `dvh`,
`scroll-snap`) совпадают, лейаут совпадает — расходится только сглаживание
текста.

⚠️ **Одна платформенная особенность Safari.** Tab там по умолчанию не
переходит на кнопки и ссылки вообще: это системная настройка
«Keyboard navigation», выключенная по умолчанию, и она действует на все сайты,
а не только на этот. Проверено: в Chromium и Firefox Tab идёт по кнопкам как
надо, в WebKit фокус остаётся на `body`. При этом сам механизм кольца фокуса в
WebKit работает — программный `.focus()` срабатывает, `:focus-visible`
матчится, кольцо появляется в `box-shadow`. Включается в
System Settings → Keyboard → Keyboard navigation.

⚠️ Проверялось только в Chrome. Safari и Firefox стоит открыть руками.
